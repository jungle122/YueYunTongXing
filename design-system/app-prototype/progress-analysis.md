# 学习反馈检查

本轮只检查正式逻辑，未修改正式页面或业务代码。

## 发现
- learn.js 对当前目录各资源的进度取平均：6 首音频、4 篇文章。不是只读取最近资源。
- audio-player.js 的 persistProgress 以资源 ID 保留整张进度表，但直接覆盖该资源的值。播放结束保存100，单曲循环将当前进度置0；暂停、退出、拖动均可保存更小值。因此“播放位置”会冲掉“曾经听完”的含义。
- 隔离执行原 persistProgress：六首均100，重播两首并分别保存2、0后，平均为67。此为代码路径复现，不代表已经取得用户那次真实运行日志。
- 文章阅读过程使用 Math.max 保持进度不倒退，但进入文章会至少计10%，说明百分比也不是严格的阅读完成凭证。

## 建议
- 分类入口改为“已听完 x / 6 首”“已读完 x / 4 篇”，保留资源级播放位置用于继续学习。
- 将播放位置与完成记录分开；听完事件设置持久完成标记，重播不取消。文章到底或现有明确完成操作记为完成。
- 总量随目录计算，仅统计当前目录中存在的ID；不能凭当前进度反推已被覆盖的历史完成记录。旧数据仅能保守迁移现存100值，无法恢复的记录不伪造。
- 原型内三种状态均为演示：0/0、2/1、6/4，分别对应未开始、部分完成、全部完成；未接入正式存储。

## 验证
四种页面在320/375/430宽度下无横向溢出、无损坏图片，两个内容入口均可触发进度弹窗。字体沿用已确认资源。未验证微信原生显示，也未更改后端。
